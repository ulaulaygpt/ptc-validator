Validator — Local distribution

The same Validator. Available for local use.

Validator Portable is the same validator.es publication distributed so it can be preserved and run locally. It is not a separate edition of Validator.

Same application, same code

There is no web version and separate Portable version. The file tree published at validator.es is the same tree distributed as a static package: same pages, same engine, same languages, same implemented specifications and same capabilities.

The only difference is distribution: validator.es serves those files from the web; the Portable distribution lets you preserve and use them from a local environment.

When to use it

The local distribution is especially useful when the execution environment itself must also be controlled.

  • Deliberately offline work or restricted connectivity.
  • Intranets, isolated networks or devices that are not allowed to access external sites.
  • Controlled deployment inside an organisation.
  • Training, auditing or demonstrations in a reproducible environment.
  • Preserving a specific Validator publication so it can be run again in the future.

File processing is local when using validator.es as well. Portable is not a “more private” edition: it provides independence from access to the website and control over the preserved copy.

How to use it

  1. 1

    Download the official publication from Zenodo.

  2. 2

    Extract the package while preserving its folder structure.

  3. 3

    Open the application from the local tree and use Create or Verify just as on validator.es.

Specific compatibility depends on the browser, operating system and device restrictions. The publication should be used in environments tested for that release; universal compatibility is not assumed.

What it contains

The package contains all files required to run the same static application published at validator.es, including local dependencies, resources, languages and usage documentation. No separate Portable codebase is maintained.

Publication integrity

The final distribution is published as a versioned artefact. Its SHA-256 is calculated over the closed ZIP and published externally alongside the distribution. The digest is not inserted into the ZIP itself, because doing so would change the bytes it is meant to identify.

A hash can show that two copies of an artefact are identical. By itself it does not establish authorship, date, provenance or legal compliance. Publication provenance should be checked against the external record.

What it implements

Portable implements exactly the same technical corpus as the application published at validator.es. The authoritative source for versions and conformance is the Protocol and specifications page.
